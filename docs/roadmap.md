# Roadmap

> 本路线图用于说明项目的长期演进方向和当前所处阶段。
>
> 具体模块进度、短期待办事项、Bug、实验记录和细节任务不在本文维护，统一通过 Issue 或其他开发记录跟踪。

## 当前状态

项目当前处于**第一阶段：主要拓扑算法链路可用**。

当前阶段重点是打通常见数字电源拓扑所需的基础控制算法链路，使项目能够支撑电子设计竞赛电源方向中的大部分典型控制需求。

这一阶段更关注控制方法是否能够形成完整链路，并具备初步工程可用性。公共接口稳定性、完整文档、完整测试和完整异常路径将在后续阶段逐步完善。

## 阶段一：主要拓扑算法链路可用

本阶段目标是使项目从零散控制组件发展为能够支撑典型电源控制场景的算法库。

第一阶段优先覆盖的拓扑方向包括：

* Buck；
* Boost；
* 图腾柱 PFC；
* 单相离网逆变器；
* 单相并网逆变器。

有余力时，可以继续扩展：

* 双向 Buck-Boost；
* 三相离网逆变器；
* 三相并网逆变器；
* 三相整流器。

本阶段的“完整”主要指算法链路完整，包括测量量输入、信号处理、控制环计算、限幅、调制量或控制指令输出等基础流程。

本阶段暂不要求：

* 完整产品级状态机；
* 完整启动和停机流程；
* 完整故障锁存与恢复；
* 公共 API 长期稳定；
* 完整文档体系；
* 完整测试和仿真体系。

同一拓扑在第一阶段和第二阶段暂时只要求支持一种主流控制方法。多种控制策略并存留到后续阶段逐步扩展。

相关控制方法应尽量结合基础实验或硬件运行经验进行确认，但本阶段不要求为每个拓扑形成完整、正式的硬件验证报告。

## 阶段二：单模块基础工程化

本阶段目标是在算法链路可用的基础上，为主要控制模块补齐基础工程能力，使单个模块能够作为相对完整的控制单元使用。

本阶段重点包括：

* 基础控制逻辑；
* 初始化、运行、停止、复位等基础流程；
* 模块状态机切换；
* 错误事件表达；
* 故障或错误发生时的快照记录；
* 基础参数装载与运行控制；
* 常见非法调用和非法状态处理。

第二阶段不追求完整产品级调度框架，也不要求形成完整系统级控制平台。

本阶段完成后，主要模块应具备基础工程可用性，但公共接口仍允许根据后续实践继续调整。

## 阶段三：文档化与对外可理解

本阶段目标是系统整理项目介绍、API 文档、模块说明、示例代码和使用指南，使外部使用者能够理解项目定位、主要能力和适用边界。

本阶段重点包括：

* 项目介绍；
* Getting Started；
* API 文档；
* 公共头文件注释；
* 模块使用说明；
* 示例代码；
* 常见模块调用流程；
* 状态、错误、事件和快照语义说明；
* 主要拓扑控制器的基础使用示例。

本阶段完成后，新用户应能够通过文档理解这个库是什么、能做什么、不能做什么，并能参考示例将主要模块接入自己的工程。

本阶段不要求完整英文文档、完整教程站点或所有拓扑的深度应用笔记。

## 阶段四：测试与仿真完善

本阶段目标是补齐测试、仿真、分析和报告能力，使项目从“能用、能看懂”进一步发展到“能验证、能观察、能比较”。

本阶段重点包括：

* 基础单元测试；
* 接口契约测试；
* 状态切换测试；
* 错误事件和快照测试；
* 控制器黑盒测试；
* 频率响应分析；
* Bode 数据和图表生成；
* 阶跃响应、斜坡响应和饱和恢复观察；
* 简化拓扑级闭环仿真；
* 测试数据、图表和报告输出。

本阶段强调测试和仿真不仅用于判断通过或失败，也应帮助开发者观察控制器的真实行为。

本阶段不追求完整功率级高精度仿真、HIL 平台、复杂器件模型或功能安全级验证。

## 阶段五：接口整理、版本化与多控制策略扩展起步

本阶段目标是整理公共 API，明确稳定接口、实验接口和内部接口，建立版本演进规则，并开始支持同一拓扑下的多种控制策略。

本阶段重点包括：

* 公共 API 分级；
* 类型和命名整理；
* 状态、错误、事件命名统一；
* 初始化、复位、运行、停止等接口风格统一；
* 版本号语义；
* 破坏性修改规则；
* 废弃接口保留和迁移说明；
* Changelog 和 Release Note；
* 稳定模块与实验模块区分。

在多控制策略方面，本阶段开始允许同一拓扑支持多种控制方法。

不同控制方法可以拥有各自的配置、状态和运行数据。项目不强行将不同控制策略压缩成完全相同的结构，也不为了表面统一牺牲接口语义清晰度。

本阶段完成后，外部用户应能够基于某个版本使用项目，并理解哪些接口相对稳定，哪些接口仍可能变化。

## 阶段六：参数设计与离线自动整定工具

本阶段目标是在已有测试、仿真和主要控制模块的基础上，逐步建立参数设计、参数扫描、参数推荐和离线自动整定能力。

本阶段重点包括：

* 控制器参数辅助设计；
* 参数扫描；
* 滤波器参数设计；
* 频域指标评价；
* 时域指标评价；
* 参数候选比较；
* 离线自动整定；
* 参数导出；
* 设计报告生成。

本阶段优先发展离线工具，而不是直接在嵌入式运行时实现复杂在线整定。

在线自整定、模型辨识、高级优化控制、完整 HIL 平台和功能安全验证暂不作为本路线图中的必达目标，可根据项目后续发展酌情探索。

## 非必达方向

以下方向可能具有价值，但当前不作为路线图中的必达目标：

* 完整产品级调度框架；
* 大型系统级控制平台；
* 完整 HIL 测试平台；
* 在线自动整定；
* 模型辨识；
* 功能安全级验证；
* 复杂硬件示例平台；
* 所有高级拓扑的完整覆盖。

这些方向可以在未来根据实际需求、维护精力和项目成熟度重新评估。

## 路线维护原则

本文只维护长期路线和阶段目标，不维护具体任务清单。

具体任务、Bug、模块实现进度、实验记录和短期计划应通过 Issue 或其他开发记录管理。

项目路线可以根据实际开发经验调整，但应避免因单一临时需求频繁改变长期方向。
